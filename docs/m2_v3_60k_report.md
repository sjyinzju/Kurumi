## CPU 验收与训练控制

- 验证冻结 V3 载荷的 22,282 个文件哈希，按同一配置重放选样，两份 Parquet 与选样清单逐字节一致。
- 全量回读 SQLite，逐行对齐两个 Parquet 的 ID、日期、权重和三个 mask；核对 native plan 的共享状态、独立分支和 Readout 位置。
- 从独立临时路径回读真实缓存的 16 条训练和 16 条验证原样本，CPU 完成 16 个 native pack。训练模块与 Karpo 源码从迁移包内导入。
- 17 项定向 CPU 测试通过。使用合成张量验证冻结初始化合同、逐期限七维概率与 mask、更新边界验证、同分选早、断点恢复及完整 LoRA/Readout 导出与重载。
- 固定 M1 epoch 1 初始化。按当前全局每更新 4 个原样本，一遍共 15,000 次更新。更新前记录 M1 基线，第 5,000、10,000、15,000 次更新后按 J 选候选。各原样本在有效期限内等权，再应用抽样权重。候选独立保存，best.json 指向最佳冻结制品，last.pt 用于恢复。

## 迁移与启动

按 [迁移说明](m2_v3_60k_package.md) 核对压缩包和目录清单。提供原始 Karpo 基座、匹配的 provenance、M1 epoch 1 冻结 manifest 及其同目录 LoRA / Readout，再指定输出目录。

```bash
bash scripts/run_cn_efficiency_m2.sh "$BASE_MODEL" "$BASE_PROVENANCE" "$M1_MANIFEST" "$RUN_DIR"
```

这是当前单进程命令。4×A100 40 GB 分片、全局批量与真实吞吐在目标机复核，随后在 GB10 ARM64 加载原始基座与最佳 M2 完整权重。M1 真实权重身份沿用已验证发布清单，本地验收使用合成权重。
