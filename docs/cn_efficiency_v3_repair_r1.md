## 重建和使用

在 V3 检出目录运行。沿用本地已安装 Karpo 环境，指向修订后的池。生成视图时填入调用方自己的日期、目标止日或分区。

```powershell
$env:CUDA_VISIBLE_DEVICES = '-1'
$env:PYTHONPATH = "$(Get-Location)/src;$(Get-Location)/scripts"
$old = 'E:/Kurumi/artifacts/cn-efficiency-v3/pool'
$pool = 'E:/Kurumi/artifacts/cn-efficiency-v3/repair/r1/pool'
$tokenizer = 'E:/Kurumi/artifacts/karpo-b8e6fd7'
python scripts/build_cn_efficiency_v3.py --from-v3 $old --config configs/training/cn_efficiency_v3.json --output $pool
python scripts/select_cn_efficiency_view.py --pool $pool --output $fitView --start $fitStart --end $fitEnd --label-end $lastTarget
python scripts/train_cn_efficiency.py --config "$pool/training.json" prepare --pool $pool --date-view $fitView --tokenizer $tokenizer --view $nativeSQLite --formats compact
```

准备器把 encoder 上限设为配置的 `max_length` 与 `pack_tokens` 的较小值。拆包重算的共享前缀只计一次有效 token，实际物理前缀成本另记。训练入口使用 `--device` 选择调度器可见的 CUDA ordinal，按能力和内存设置检查，默认每小时保存恢复点并可配置。正式训练和任何文本 M3 分支使用同一个封存 M1 初始化。
