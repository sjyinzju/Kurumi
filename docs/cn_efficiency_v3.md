## CPU 和迁移

同 1,024 条每臂三个独立 CPU 进程。初次墙钟 14.41→11.12 秒，后两次均值 13.02→10.75 秒，操作系统页缓存未经清理。同期工作量 4,492,656→3,024,079 token。V3 保留短段分词、日内上下文复用和历史数组直传。相同 V3 文本的旧字典路径、无日内复用、延迟读共享表和 512 批大小中位墙钟各为 11.24、11.00、10.92、11.58 秒，计划及目标摘要逐臂相等。8,192 上限下，多原样本包从 0 增至 512 个。GPU 吞吐和显存待测。

迁移副本核对了 43 个文件的哈希。隔离进程禁用 DuckDB 外部路径并记录本地文件打开，复核 Arrow 和 Python 的数据访问。两个视图 383 和 191 条，监督分别为 [383, 324, 129]、[191, 169, 87]。574 条缓存与直接原生编码逐条一致。验收了 2 个单原样本包、286 个双原样本包、三期限强制拆包及 mask 和权重下的损失分母。 [原生验收](cn_efficiency_v3_evidence/portability.json)

推进顺序为单位和边界去重复、20/15/10 日密集窗口和远期锚点、价格档、CPU 关联和批次。2/5 bp 在近期真实文本中分别让 11、138 个已保留的非零 OHL 价差归零，结束该轮。延迟关联和批次缩小没有令同任务稳定提速 5%，完成第二轮。临时脚本、候选中间缓存、迁移副本、试验 SQLite 已清理。发布清单中的构建器哈希来自实际生成，工作树最后一次改动仅整理其导入空行。

## 重建与准备

从 V3 工作树执行。`$fitStart`、`$fitEnd`、`$lastTarget`、`$tokenBudget` 和输出路径使用自己选择的值。编码使用本地模型配置及 tokenizer。

```powershell
$py = 'E:/Kurumi/artifacts/cn-efficiency-v2-work/venv/Scripts/python.exe'
$pool = 'E:/Kurumi/artifacts/cn-efficiency-v3/pool'
$tokenizer = 'E:/Kurumi/artifacts/karpo-b8e6fd7'
$env:PYTHONPATH = "$(Get-Location)/src;$(Get-Location)/scripts"
$env:CUDA_VISIBLE_DEVICES = '-1'
$env:HF_HUB_OFFLINE = '1'
$env:TRANSFORMERS_OFFLINE = '1'
$env:TOKENIZERS_PARALLELISM = 'false'
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '3'

& $py scripts/select_cn_efficiency_view.py --pool $pool --output $fitView --start $fitStart --end $fitEnd --label-end $lastTarget --token-budget $tokenBudget
& $py scripts/train_cn_efficiency.py --config "$pool/training.json" prepare --pool $pool --date-view $fitView --tokenizer $tokenizer --view $preparedSQLite --formats compact
```
